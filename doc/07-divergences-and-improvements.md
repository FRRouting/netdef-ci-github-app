## 2. Odd behaviors **deliberately preserved**

- `PullRequest#plans` is `has_many` by `plans.pull_request_id`: when an event is received, **the repository's plans become owned by the most recent PR** and old PRs are left without plans (the `ci:rerun` flows fall back to `Plan.where(github_repo_name)`). Changing this would require a new association table.
- Finishing a stage (`success/failure/cancelled`) **creates a new check run** and concludes it (the old check run remains); `Stage#enqueue` also creates a new one.
- `CreateExecutionByCommand` (check_suite re-request) does not associate the plan with the new suite (`plan_id` NULL).
- `Build::Retry` looks up the stage by `github_check_run_name` (without the `multi_plan?` suffix).
- A late (`success`) callback for an already `cancelled` job is accepted (only `queued`/`in_progress` have the 304 guard).
- `CiJobFetchTopotestFailures` discards results when `count > 3` even if there are failures.
- `ci:retry` and `ci:rerun` in the same message: `retry` wins.
- `update_execution_time` uses the first `in_progress` and the first `success/failure` (accumulates re-executions).
- `ReRun` (sha): `UnavailableJobs` runs over **all** suites of the same commit and moves missing jobs to the new suite.

## 3. Behavior changes (improvements) — all deliberate

| Improvement                                                                                                                    | Reason                                                                                            |
|--------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| Installation token caching and renewal; JWT with back-dated `iat`; a `401` renews the token                                    | Ruby created a JWT + token on **every** `Github::Check.new` (hundreds of calls per execution)     |
| Limited retries: reads/PATCH on transient failures, any method on rate limit/`Retry-After`; **no POST retry** on network error | resilience without repeating non-idempotent effects                                               |
| Jobs that start a plan in Bamboo (`create_execution_by_*`) have `max_attempts = 1`                                             | in Ruby a late failure repeated the job up to 5× and could start several plans                    |
| Advisory lock per PR in the creation/cancellation flows                                                                        | rapid events on the same PR do not cancel/create concurrent executions (race that exists in Ruby) |
| Auxiliary failures do not abort the flow: comment reactions, GitHub user data lookup, Slack                                    | they used to break the PR processing                                                              |
| `Finished` responds `503` and **changes nothing** if Bamboo is unavailable                                                     | Ruby raised `NoMethodError` and the WatchDog aborted on the first case                            |
| Webhook authentication **before** `JSON.parse`; invalid JSON → `400` (Ruby: 500); no `X-GitHub-Event` → `400` (Ruby: 500)      | hardening, no impact on legitimate clients                                                        |
| Secrets never in logs; the Bamboo submission URL is not logged; headers/`request.env` are not dumped at DEBUG                  | Ruby logged the full env and the URL with `signature_secret`                                      |
| Comments sent to Bamboo have XML escaped; query string encoded by the HTTP client                                              | Ruby concatenated raw text                                                                        |
| `output.summary` limited to 65,535 characters                                                                                  | GitHub rejects (422) larger summaries                                                             |
| `check_runs` listed with `per_page=100`                                                                                        | Ruby stayed on the 1st page of 30                                                                 |
| `ci:rerun #sha` ignores whitespace/line breaks around the sha                                                                  | `"#abc123\n"` did not match                                                                       |
| Tolerance to incomplete PR/payload → `422` instead of an invalid record                                                        | ActiveRecord validations were silent                                                              |
| Optional deduplication by `X-GitHub-Delivery` (`WEBHOOK_DEDUPE_TTL_SECONDS`)                                                   | off by default (GitHub's *Redeliver* button reuses the id)                                        |
| `GET /healthz`, `GET /readyz`; `/telemetry` with version/uptime/pool                                                           | health checks for systemd/Ansible/load balancers                                                  |
| Slack TLS verified by default (`SLACK_BOT_VERIFY_TLS=true`); Bamboo keeps `false` by default (loopback)                        | Ruby never verified TLS; adjust if the Slack bot certificate is self-signed                       |
| File logs with `WatchedFileHandler` + logrotate                                                                                | several processes write the same files                                                            |
| Per-queue-range workers managed by systemd                                                                                     | see divergence no. 1                                                                              |
| systemd timers instead of cron                                                                                                 | `Persistent=true`, logs in the journal, controlled by Ansible                                     |

## 4. Metrics not replicated

`puma_*` (there is no Puma) and `http_server_*` (Rack middleware) do not exist; `activerecord_queries_total{table}` uses the SQL **table** name (`ci_jobs`) instead of the model name (`cijob`). Panels in `grafana_dashboard.json` that use these labels need adjusting.
