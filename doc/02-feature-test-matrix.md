# 02 — Feature and test matrix

## What the service does

| Topic                     | Description                                                                                                                                                                                                                                                                                                             |
|---------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Endpoints                 | `POST /*` (GitHub webhooks, any path), `POST /update/status` (Bamboo callbacks), `POST /slack`, `POST /slack/settings`, `GET /metrics`, `GET /telemetry`, `GET /ping`, `GET /healthz`, `GET /readyz`                                                                                                                    |
| GitHub events             | `ping`, `pull_request` (`opened`/`synchronize`/`reopened`), `check_run` (`rerequested`), `check_suite` (`rerequested`), `issue_comment` (`ci:retry`, `ci:rerun [#sha]`), `installation`; any other event is answered with 401                                                                                           |
| GitHub App authentication | JWT RS256 (`iss` = App ID, short validity) → first installation → installation token; the token is cached and renewed                                                                                                                                                                                                   |
| Webhook validation        | HMAC-SHA256 of the raw body with the webhook secret, from the `Signature` or `X-Hub-Signature-256` header; the same secret is sent to Bamboo, which signs its callbacks                                                                                                                                                 |
| Persistence               | PostgreSQL: 13 domain tables plus `jobs` (background queue) and `webhook_deliveries` (optional deduplication), managed by Alembic                                                                                                                                                                                       |
| Queues / async            | Table-backed job queue (`jobs`): numeric queues 0–9 (`github_pr_id % 10`) and named queues (`create_execution_by_*` and `retry_execution`, optionally partitioned by PR, `timeout_execution`, `fetch_topotest_failures`); backoff retries, `max_run_time` limit, one worker process per queue set (one per named queue) |
| Scheduled tasks           | `timeout_execution` (self-rescheduling job, 10 min / 2 h thresholds); systemd timers for `watch-dog` and `pr-bamboo-sync`; manual `single-sync`                                                                                                                                                                         |
| Integrations              | GitHub (Checks, Pulls, Issues/Reactions, Users), Bamboo REST API, Slack bot, Prometheus                                                                                                                                                                                                                                 |
| Secrets / configuration   | Environment variables (see `04-configuration-and-environment.md`), GitHub App `.pem` keys, Bamboo and Slack credentials, metrics Basic Auth                                                                                                                                                                             |
